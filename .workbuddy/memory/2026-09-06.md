## 【二轮】workflow.png 被 16:9 cover 裁切
- 用户反馈：workflow.png 在「从意图到构件」一节只显示上半 + 下边一小角，中间大片空白。
- 根因：图原 1173×349（3.36:1 横向长条），但 `.campaign-feature` 全局 `aspect-ratio:16/9 + object-fit:cover`，
  cover 强行垂直放大把上下全切掉，露出中部留白。
- 修法（仅动单图，不影响其他 campaign-feature 的 16:9 cover 默认）：
  - CSS 加 `.campaign-feature--flow { aspect-ratio:auto; background:var(--paper); }`
    和 `.campaign-feature--flow img { height:auto; max-height:none; object-fit:contain; }`；
  - workflow 那张 `<figure>` 加 modifier 类 `campaign-feature campaign-feature--flow`。
- 验证：容器 1163×346，img object-fit=contain，整图完整显示，无横向溢出。
- 适用场景：任何原图比例明显横长（如 workflow、流程图、长 banner）用 --flow；其它 16:9 风景照仍 cover。

## index.html 移动端罗盘布局重构（iPhone SE/13 Pro 标签溢出修复）

### 问题 v1：标签挤在罗盘内部
手机端（iPhone SE 375px、iPhone 13 Pro 390px、iPhone 16 Pro Max 440px）下，
首屏 SVG 罗盘的 3 条 `.annotation-text` 标签（`01 / AI 集群建造`、`02 / AIGC 视觉设计`、
`03 / AIGC 产品化`）分布在 viewBox `0 0 300 300` 的外侧（`x=310` 超出右边界、
`x=-120` 在左边界外），被 `.viewport { overflow: hidden }` 裁切。

### v1 失败 → v2 修正（用户反馈"所有的内容都挤在中间最小处了"）
第一版把标签平移到 viewBox 内的 (150, 220/245/270)，结果标签还在罗盘圆的内部，
和底部弧段叠在一起。原因：默认 `<svg>` 在现代浏览器 UA 是 `overflow: hidden`，
y > 300 的 viewBox 之外区域根本不会被渲染；而且我把 y 设成了 220-270，完全在罗盘内。

### v2 修正（让标签溢出 viewBox 真正出现在罗盘下方）
- `.compass-svg { overflow: visible; }` —— 关键，让 SVG 标签可以溢出 viewBox
- 标签平移到 viewBox 之外（y=315/350/385）
- 罗盘大小保持原 1000px 断点的 min(440, 51vw, 50vh) ≈ 191-228px

### v2 失败 → v3 放大罗盘（用户反馈"整个内容都太小了，把圆和半圆弧放大至少1.35倍"）
v2 解决"标签在哪里"但没解决"标签为什么这么小"。用户要求罗盘本身 ≥1.35x，
同时弧底与首条标签间距要拉大。

### v3 方案：
1. 罗盘从 `min(440, 51vw, 50vh)` → `min(440, 75vw, 55vh)`，给到 1.47x：
   - 440px 屏：75vw=330 → 1.47x ✓
   - 414px 屏（XR）：75vw=310 → 1.47x ✓
   - 375px 屏（SE）：75vw=281 → 1.47x ✓
2. 标签 y 坐标再往下一档：315/350/385 → 345/380/415
   - 弧底 viewBox y=285 → 首条标签 y=345：可视间距 ≈ 50-70px（按当前罗盘浮动）
   - 同步调整 translate delta：
     - 01: translate(-160px, 267px)
     - 02: translate(-160px, 155px)
     - 03: translate(270px, 337px)

### 关键技巧
- `.annotation-text` 是 SVG `<text>` 元素，用 SVG 用户坐标系的 `transform: translate(dx, dy)` 平移
- `:nth-of-type` 在 `.compass-svg` 内只匹配 3 个 `<text>`，顺序天然就是 01/02/03，无需新 class
- 必须显式 `.compass-svg { overflow: visible; }`，否则 viewBox 之外的标签看不到
- viewBox y 在更大罗盘下自动带来更大的可视间距（y * scale）

## index.html iPhone 13 Pro：作品集底部 meta 文字被 Safari 工具栏遮挡 → 方案 A
- 现象（用户截图）：进入 portfolio 后卡片正常（prev/active/next 三条），
  但卡片下方 `.meta`（项目名+类型年份）在真实 iPhone 上不可见。
- 复现与根因：390×844 布局视口下 `.meta` bottom: 7vh≈59px → y 740-785，CSS 视口内可见；
  但真机 Safari 底部工具栏(~83px) + Home Indicator(~34px) 把可见区域压到 y≈761 以下 → 文字被盖住。
  截图可用但真机不可见 = 「布局视口可见 ≠ 可视视口可见」的典型案例。
- 修复（用户选定方案 A：env safe-area）：
  1. `<meta name="viewport">` 加 `viewport-fit=cover`（否则 iOS env() 恒为 0）；
  2. ≤1200px 平板段 `.meta { bottom: 8vh }` → `calc(8vh + env(safe-area-inset-bottom, 0px))`；
  3. ≤560px 手机段 `.meta { bottom: 7vh }` → `calc(10vh + env(safe-area-inset-bottom, 0px))`，
     同时 `--stack-gap` 从 15vh 收紧到 11vh，避免 next 卡片下沿(y 666)压到抬起的 meta(top 681+)。
- 验证：390px 下 meta bottom=84.4px(env=0 模拟) top 715 < 844 可见、nextCardBottom 666 无重叠、
  overflowX=0；桌面 1440 走 top:50% 左栏规则完全不受影响。
- 经验：桌面/截图工具验证移动端 bottom 定位必踩 Safari chrome 坑 → 统一用 `env(safe-area-inset-bottom)`
  + `viewport-fit=cover`，别用固定 vh。
