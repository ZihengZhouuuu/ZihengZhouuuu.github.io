## 修复 bug（2026-08-31 晚第二轮）

用户反馈两个 bug：
1. **Map 视图切换 sector 串色**：点击 spatial 打开 categoryPanel 后用键盘（Tab/Arrow）切换到 robotics，spatial 仍是粉色、robotics 不变绿。
   - 原因：sector 的 `focus/blur` 处理器在 `category-mode` 下提前 return，导致 `touch-active` 类无法添加/移除。
   - 修复：focus/blur 移除 `category-mode` 守卫，仅保留 `journeyLock` 守卫。

2. **Index 视图携带 journey 残留颜色**（图4：圆环变形放大 + 背景粉色 + arc 残留绿色）：
   - 原因：frame() 检测到 `index-mode` / `category-mode` 时提前 return，导致 `applyJourney` 不再执行，journey 状态（bgTint、bg-hero 图片、sector is-live/transform/pattern）不被清除。
   - 修复：新增 `resetJourneyVisuals()`，在 `setViewMode("index")` 和 `closeCategory()` 中主动调用，统一清除 bgTint.transparent、bg-hero img.active、stage/compassSvg transform、sector is-live/pointerEvents/tabindex、bgPattern（通过 `window.setPattern` 暴露后调用）。initJourney 中将 `setPattern` 挂到 `window` 以便全局调用。

经验：**frame() 的 index/category-mode early-return 让 journey 状态无清理出口**——任何"切走覆盖层"的路径都必须主动归位视觉状态，不能依赖 journey 自动 pause。建议后续在所有跨模式切换点（view toggle、ESC、closeCategory 等）都调用 `resetJourneyVisuals()`。

## 回滚：纯 hover 驱动 + 修复偏移（2026-08-31 晚第四轮）

用户反馈"颜色应该随着点击另一些部分就取消了，也不应该再固定在 hover 的位置了，改的都不对"——pinnedSensor 锁定方案被否决。

回滚操作：
- 删除 `pinnedSector`、`unpinSector`，相关 8 处引用全部移除。
- sector 的 focus/blur 处理器恢复 category-mode 守卫（最初行为）。
- sector 的 focus 处理器去掉 category-mode 下的"仅预览不抢高亮"分支。

修复 stage 偏移（这是用户截图圆环跑到右下的真因）：
- `@media (min-width:769px) and (max-width:1100px) and (max-height:760px)`（Nest Hub 媒体查询）中的 `.compass-stage { position:absolute; left:63%; top:47%; ... !important }` 整块删除——这个规则在矮屏横向把 stage 推到屏幕右半部。
- iPad portrait 媒体查询的 `.compass-stage { position:absolute; left:50%; top:34% }` 保留（但 transform 由 JS 控制，不冲突）。

补漏：
- `openCategory` 现在也调用 `resetJourneyVisuals()`——之前只在 closeCategory / setViewMode("index") 中调用，导致从旅程模式点 sector 打开面板时 stage transform 没清，圆环偏移。

经验：JS 已通过 `applyJourney` 完全控制 stage position/scale 时，CSS 媒体查询不应再覆盖 position/transform——这是布局偏移的常见来源。
