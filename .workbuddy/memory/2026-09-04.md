## 实测方法与结论（agent-browser）
- **坑**：agent-browser 的浏览器在「跨 Bash 调用」之间会掉线（下次命令 get url 变 about:blank）。
  必须把 `open → sleep 3 → eval/click → close` 全放进**同一条 Bash 命令**内执行。
  `open` 后不 sleep 就 eval 也会拿到空 DOM。
- **坑**：`hover "#arc2"` 报 Element not found（SVG path 不满足 actionability），
  改用 `eval` 派发 `new MouseEvent("mouseenter")` 验证同一条监听链。
- 实测结果：hover arc2 → 下滑进 activeCard=3「极端环境无人建造」；
  hover arc1 → 下滑进 activeCard=2「自然语言需求转化」；作品集页点 ABOUT → `in-portfolio in-footer`
  且 footer transform 归零；首屏点 ABOUT → 形变后 footer 到位、compass opacity 0 / pointer-events none；
  页尾上滚 → 回到 `in-portfolio`，footer 滑出视口。
- **既有缺口（当日晚些已补上）**：`switchState()` 原本没有 footer→hero 分支，处于页尾时点左上角 brand
  无反应。已加 `else if (currentState === "footer" && targetState === "hero") { returnToHero(); }`。
  `returnToHero()` 内部已 `classList.remove("in-portfolio","in-footer","is-morphing")`，无需再手动清 in-footer。

## Index_Super_Simple.html：修复弧线渐变的方形色块（用户截图反馈）
- 症状：hover 时弧线中部出现**带硬边的方形亮条**（arc2 尤其明显）。
- 两个根因：
  1. 6 个 linearGradient 用默认 `objectBoundingBox`——渐变坐标按每条弧自身包围盒映射，
     arc2 几何包围盒仅 10px 宽（45° 短弧 x:20-30），渐变被非均匀压扁且与包围盒边缘耦合；
  2. `.arc-sheen` 的 `filter` 区域 `x="-20%" width="140%"` 也按包围盒百分比算——
     arc2 的模糊白光被硬裁剪到 x∈[18,32] 的窄竖条，即用户截图里的方形亮边（主凶）。
- 修复（用户思路「扩大渐变范围」）：
  1. 6 个渐变全部 `gradientUnits="userSpaceOnUse"`，向量 = 各弧弦向两端各延伸 50%
     （arc0: (90,-20)→(330,140) / arc1: (330,160)→(90,320) / arc2: (30,250)→(30,50)），
     每条弧只采样渐变全程的 25%~75%，两端留缓冲，方向与原设计一致；
  2. `sheenBlur` 滤镜改 `filterUnits="userSpaceOnUse" x="-40" y="-40" width="380" height="380"`，
     固定覆盖整圆+描边+模糊外溢，白光不再被裁。
- 验证：截图对比（常规态 / eval 加 .active 模拟 hover 态）——方形亮条消失，hover 时亮金属渐变 +
  柔和白光贴弧流动；常规态三弧呈均匀极暗渐变。
- 经验：**SVG 渐变/滤镜的百分比区域都是相对元素几何包围盒的，窄长包围盒（短弧、近垂直线段）
  会把渐变压扁、把滤镜输出裁成矩形；涉及弧段的渐变和 blur 滤镜一律 userSpaceOnUse 并给足余量。**
